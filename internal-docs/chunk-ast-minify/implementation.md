# Chunk AST Minification — Implementation

## Summary

The chunk AST pipeline is the sole minification path for supported JavaScript chunks. It assembles finalized module ASTs into one chunk program, compresses/mangles it, then prints module segments against a shared virtual source space. Flat chunks avoid printing and reparsing the joined chunk; retained complete programs cover wrappers, inline carriers, dev output and unchanged hook results. Only actual text returned by `renderChunk` or produced by arbitrary executable addons is reparsed into the same optimizer.

## Source maps

`crates/rolldown/src/stages/generate_stage/chunk_ast_dce/global.rs` rebases module spans into the shared source text. After printing, `remap` assigns each token to its original producer. A virtual owner can contain code moved from a real module, so its map must still be generated.

- A map containing only its real owner's source can defer transform-chain composition to the normal module renderer.
- Foreign producers are composed with their own transform chains. Their maps are final even when those chains are empty; the printed owner's chain must not be applied afterward.
- Virtual and generated source locations, and already-unmapped input tokens, produce explicit unmapped segments. Dropping these tokens would let a preceding mapping extend across generated code on the same output line, especially with whitespace minification.
- `compose_per_module` composes mapped tokens by producer and carries unmapped tokens through unchanged, then merges them in generated order. The unmapped segments must survive even when another producer has a transform chain. Composition may omit a producer's wholly unmapped line or repeated unmapped segments (for example after a plugin returns an empty map); preserve explicit unmapped segments at omitted generated positions before merging it with foreign producers on that same line. A foreign mapped producer can intervene between two such positions, so retaining only the line's first boundary is insufficient. `empty_producer_map_terminates_foreign_mapping` checks this boundary and both neighboring donors in serialized final maps, in DCE-only and full-minify modes.
- `rolldown_sourcemap::SourceJoiner` repairs `oxc_sourcemap` 9 concat chunk headers to carry the last mapped original line/column across unmapped fragment endings. Unmapped segments leave those VLQ baselines unchanged; using their placeholder coordinates corrupts the following fragment's serialized map even while its in-memory tokens remain correct. The serialization roundtrip regression covers mapped/unmapped endings, consecutive unmapped fragments, repeated sources, and name baselines.

The vendored `oxc_minifier` exposes `Minifier::with_literal_spans` and `Compressor::with_literal_spans`, enabled only by the global path when sourcemaps are requested. Builder methods preserve compatibility with existing `CompressOptions` struct initializers, including the native binding's upstream conversion. Constant inlining otherwise rebuilds literal nodes with the consumer identifier span, losing atomic donor origins entirely. The opt-in records original direct variable-initializer literal spans during the existing Normalize traversal, before folding, sorts them once at Normalize completion, and carries their provenance through symbol aliases and direct AST moves. Both lookup consumers inspect declarator initializers, so literals in other expression positions need not be recorded. Composite folds keep consumer attribution. Consumers or donors with anchored comments also keep consumer attribution, preserving annotation placement and avoiding duplicated donor comments. The assembled compression program receives a copy of module comment metadata for this guard; module codegen continues to print the originals. Tracking adds enabled-only provenance/comment buffers and declarator hooks to Normalize, with no additional whole-AST scan; the disabled path does not allocate those buffers or run provenance recording. See `vendor/oxc_minifier.patch`. Integration assertions in `literal_provenance`, `plugin_sourcemap_chain` and `sourcemap_audit` cover serialized donor positions, producer transform chains and consumer comments. The pinned MapLibre 6.16.0 audit exercises the native Node API across original/global × compress/mangle/full: all 54 selected upstream artifact tests pass, and all 64 inspected shader values retain exact donor mappings in each global mode. Identical shader values may share a real donor. Original compressed output retains consumer attribution, while its standalone source inventory still lists the donor. The now-unused JSON source can be absent from global compressed maps; source-list identity is not required.

The integration regression `full_minify/virtual_owner.rs` checks exact real-source locations and the adjacent virtual-code boundary with and without a producer transform map, in DCE-only and full-minify modes. The `global/tests.rs` unit regression also covers generated text, incoming unmapped segments, and restoration of a mapping after each boundary.

The `sourcemap_audit` integration regression checks original-source anchors in fifteen existing fixtures using serialized/reparsed final maps, including shorthand key/value pairs, imported CommonJS calls, destructuring and reference endpoints. `plugin_sourcemap_chain::composed_source_positions` checks a separate plugin-transform fixture in ordinary and full-minify modes, asserts that all three producers really run through the transform, and checks foreign-source positions after composition. Run these as default-pipeline regressions. Historical dual-path audits did not require the two paths' segment counts or synthesized punctuation anchors to be identical: inlined outer nodes retain reference spans, so direct codegen can use the reference's end while reparse/composition resolves to its start.

A synthesized block's closing brace must terminate mapped child coverage. The vendored codegen emits an explicit unmapped segment for an empty block closing span, and clears mapping deduplication state so the same original position can resume afterward. This is scoped to block/curly closing braces; synthesized call delimiters retain their existing reference-attribution behavior. Without this boundary, a minified CommonJS wrapper's closing glue inherits the last user statement's location. The regression checks the last real closing brace, every intervening generated byte, and the next real call; the codegen unit regression exercises the same transition without bundling.

## Splitting

The debug build compares the minifier's statement-address sequence with the flattened head/module/tail segments. Printing may change ownership attribution but must preserve statement order. Class offsets passed to codegen must follow that same traversal order for private-member mangling.

## Render hooks

Chunks with user `renderChunk` hooks defer optimization. Preliminary module printing preserves annotations and supplies the existing pre-minification module metadata. The finalized donor ASTs are then assembled into an exclusively owned `PendingChunk`, carried separately from the borrowed `GenerateContext` across asynchronous rendering and hooks. `renderChunk` and `augmentChunkHash` retain their existing invocation order. If every render hook returns `None`, the retained program enters the shared AST optimizer and its final maps are rebuilt from producer provenance. If any hook returns `Some(code)`, even identical text, the retained owner is discarded: the final text is parsed and passed to the same optimizer, preserving the hook's map disposition. Parsing arbitrary plugin text is an input adapter, not evidence that unsupported renderer shapes have migrated.

Concrete `Pluginable::is<T>()` checks distinguish builtin asset/copy hooks and the test marker plugin from user hooks; plugin names cannot bypass deferral. Asset/copy chunks defer when their module or generated glue contains emitted-file placeholders, so builtin rewrites finish before optimization. Ordinary chunks retain early optimization. See [plugin-asset-module](../plugin-asset-module/implementation.md). The test marker implementation lives in `rolldown_plugin_utils` behind its `testing` feature and only rewrites comment lines.

The retained path reconstructs hashbang, comment-only banner/footer, directives and legal debug headers around optimized fragments. Directive rendering uses the format renderer's shared helper: appending another semicolon can terminate a multi-directive prologue and invalidate the optimizer's strictness assumptions. `render_hooks` executes unchanged/replaced ESM/CJS/IIFE/UMD output, checks original map anchors, CJS directive semantics and debug-header comment policy.

## Ownership and concurrency

`owned.rs` consumes eligible `EcmaAst`s into a `Pin<Box<ChunkAst>>` before detaching any roots. `PhantomPinned` prevents safe unpinning; `PreparedChunk` and `PendingChunk` transfer only the pinned box handle, and all assembly and optimization mutate fields in place. Moving an ordinary owner after creating its roots is unsound: Miri's Stacked Borrows model rejected that design because the roots contain references into the owner's donor cells and scratch allocator.

It detaches each whole `Program`, replaces its original root with an empty program, and retains the original `ProgramCell` intact as an arena/source keepalive. Do not use `ProgramCell::into_owner()`: Oxc arena vectors retain an `&Arena` inside the allocator object, so moving that allocator out of the cell invalidates retained vectors even if the arena buffers survive. `programs` and `donors` reserve the exact final module count. Each donor is pushed into its final Vec slot **before** its root is detached, and assertions reject any push that would reallocate either Vec and relocate existing donors or roots. The caller constructs that count from the file's own modules plus all retained inline-carrier modules.

The chunk scratch allocator is boxed before any scratch allocations, and the owner retains the shared source text before rebasing installs references. Programs and the optional assembled root are declared before donor cells, scratch and source keepalives, so every root retires before backing storage during normal drop and unwinding. A deferred owner is `Send`, not `Sync`; only the frozen `PreparedChunk` exposes parallel read-only printing. Preparation consumes the pinned handle; a panic cannot leave partly changed roots accessible through the original AST table.

Only pre-assembly rebasing transfers individual `ChunkProgram`s between workers, while their donor arenas are still disjoint. Once bodies mix arenas, compression and splitting run serially per chunk. `PreparedChunk` is a frozen facade: its only shared operation prints a module into owned code/maps. It exposes no AST, semantic cells, allocator or generic callback. Its localized unsafe `Sync` implementation relies on codegen reading ASTs without mutating cells or allocating into their arenas. All readers join before consumption/drop. Cross-arena programs never re-enter an ordinary `EcmaAst`.

This retains parallel chunk preparation, span rebasing and module printing without cloning AST nodes, locks or per-node reference counts. It adds one pinned chunk-owner allocation, one boxed scratch allocator, and root/keepalive vector storage per minified chunk; it does not add a per-module root/donor box. Minification-disabled builds do not construct these owners. Unit tests exercise allocator-address stability after owner/thread moves, scratch-vector growth, mixed-donor printing during unwind, source release and joined parallel readers. The final owner passes all three tests natively, under Miri with Stacked Borrows, and under AddressSanitizer.

## Module metadata

`RenderedModule.code` describes the emitted fragment owned by that module, not its original-source contribution. For retained AST programs, `renderChunk` and `augmentChunkHash` receive immutable preliminary `Arc<RollupRenderedChunk>` snapshots; after optimization, `generateBundle` and returned output receive a new final metadata object containing compressed/mangled fragments. Copy-on-write must not mutate either preliminary snapshot. Inlining and statement merging can move code between module segments or into generated head/tail code. A donor literal moved into a consumer statement belongs to the consumer even when sourcemaps point to the donor. An emptied segment has `code: null`, `renderedLength: 0` and zero rendered byte length; the module remains in `modules` and `moduleIds`. `renderedLength` counts UTF-16 code units of that fragment. Generated wrappers, factories, bridges, graph registration, imports and export glue are not assigned to a module merely because they surround donor nodes. Fragments need not be independently executable.

Actual text changed by `renderChunk` and arbitrary addon text retain preliminary module metadata: sparse sourcemaps cannot reliably reconstruct final ownership after reparsing arbitrary text. Module IDs and `renderedExports` retain link-stage identity even when their code is inlined elsewhere. This post-compression attribution can change size reports and final metadata compared with the former late text pipeline.

Vendored codegen optionally records ordered, nonoverlapping output byte ranges from real donor spans. Statement/expression frontiers assign an entire moved subtree to its consumer, including iterative binary printing and direct CJS literal printers; generated outer statements remain transparent. Pending semicolons retain the preceding owner, orphan comments include their layout, adjacent same-owner ranges coalesce, and `SPAN` is unowned. Recording is disabled by default and does not allocate recorder storage; enabling it must not change code or serialized maps. `output_ranges.rs` and `metadata_audit` cover these boundaries, ESM/CJS/IIFE/UMD, DCE/full minify, inline/dev generated-glue exclusion, Unicode lengths, and preliminary/final snapshot consistency.

## Path coverage

With the `testing` feature, `ROLLDOWN_CHUNK_AST_COVERAGE=/absolute/path.jsonl` records the first failed build/chunk gate, actual global execution, completed optimization/splitting, per-module printing, and whether the late text minifier runs or skips an AST-processed chunk. Records include cwd/output directory, preliminary chunk/module name, and normalized compress/mangle/property-mangle flags. The append-only writer is serialized for parallel jobs within one process; use separate trace files for separate Node processes/workers, since their writes to a shared path can interleave. No tracing code or file access is compiled into builds without `testing`. The trace is opt-in and is not a benchmark.

`path_coverage::execution_and_final_maps` exercises compress-only, mangle-only and full minify across cross-module inlining, duplicate/nested private fields, dynamic splitting, comment-only banners, CJS/IIFE/custom-renderChunk, and executable intro/banner inputs. Each run executes 27 builds in Node with concrete value/event-order assertions, checks 33 final maps and 60 exact original-source anchors, and optionally exports raw code/maps through `ROLLDOWN_PATH_MATRIX_OUTPUT`. Coverage distinguishes retained AST optimization from final-text inputs; addon cases enter `addon_text`, hook replacements `hook_text`, and all other minified chunks skip late parsing. Compare chunk graph roles/references rather than hashed filenames, which legitimately change with emitted bytes.

## Sole pipeline and admitted inputs

There is no `ROLLDOWN_CHUNK_AST_DCE` mode switch, strict migration gate, marker/address splitting implementation, or uncovered original-minifier route. Disabled minification still uses ordinary rendering, and declaration chunks/non-Ecma assets are excluded from optimization. Every minifiable JavaScript chunk must either have completed early AST optimization, retain a deferred AST, or be explicitly marked as actual hook/addon text. A missing admitted input is an internal invariant violation; it must never silently optimize the original printed chunk through a fallback route.

`GenerateStage::minify_chunks` preserves disabled-minify behavior and multiple-chunk property-mangling validation. `optimize_final_text` is the sole parser adapter for actual changed `renderChunk` text and arbitrary executable addons. It shares `EcmaCompiler::minify_program` with early and retained AST inputs; its existence does not imply that unchanged chunks or module sources are reparsed. Prebuilt chunks emitted later by `generateBundle` do not pass this boundary.

Wrapped ESM entry initialization enters the same assembled program. `render_wrapped_entry_chunk` remains the single source of truth for synchronous/awaited own initialization, re-export initialization, and ordered consumer-local targets (including CJS carriers). Its generated text is parsed before compression, followed by generated exports, and optimized together with the finalized wrapper ASTs. The renderer suppresses the original tail, avoiding a second invocation.

`wrapped_entry` regressions execute default DCE, compress-only, mangle-only and full modes. They check awaited dependency ordering, live bindings and once-only initialization; a shared asynchronous dependency across entries with strict execution order disabled; generated-only facades with inert shared implementation chunks; and consumer-local namespace targets with ordered ESM/CJS effects. Both wrap-all and on-demand variants are checked where they produce these shapes, together with serialized/reparsed final maps and exact user-source anchors. A zero-module facade can place its entire optimized program in the generated head, preserving statement order; its generated map must stay unmapped. Do not require per-module print events for such facades.

Generated ESM external-star re-exports enter the assembled import head using the same renderer as ordinary output; `render_esm` suppresses duplicate emission. Finalized donor bodies can also retain top-level external namespace imports for dynamic re-exports. Assembly consumes these existing nodes in their actual positions; no marker-splitting restriction remains. `generated_glue::finalized_external_imports_preserve_live_reexports` covers live reads through a CommonJS consumer, external evaluation order, four minify configurations and serialized donor-map anchors. CJS assembles namespace markers before the runtime module, then requires/interop, user modules and wrapped-entry/export glue. Its strictness comes from the output directive context. `cjs` and `generated_glue` regressions exercise DCE/compress/mangle/full, initialization order, live bindings and serialized final-map anchors.

Property mangling and enabled codegen-only configurations enter the same optimizer. Property caches, including seeded reservations, are returned from early AST, retained AST and final-text inputs. Multiple JavaScript chunks retain the public invalid-option diagnostic. Declaration chunks and ordinary assets are excluded from that count; validation runs again after `generateBundle` because plugins may emit prebuilt JavaScript chunks then. `property_cache` covers these boundaries.

IIFE/UMD use a reusable async `WrappedPlan` from the actual format renderer, preserving generated fragments and invoking each `globals` callback once. Its structured `WrapperAstPlan` builds the builtin outer functions, arguments, dispatch, namespace initialization and markers around finalized donor bodies in the stable scratch arena. Flat complete programs use the same assembly boundary without a wrapper function. No wrapper skeleton or EmptyStatement insertion slots remain. Namespace markers precede runtime helpers, which precede external interop. Actual user IIFE globals argument-list text, raw directives and comment-only addon snippets remain parser inputs; raw commas, spreads and user-supplied line breaks retain the renderer's argument semantics. Raw directive spelling must preserve escaped strings without accidentally introducing strict mode. Generated external interop/export fragments still use shared generated-glue parsing. The complete outer Program enters the shared optimizer, prints once and remaps through the virtual source space. Original module sources are not reparsed. Module comments are merged even when sourcemaps are disabled. Their retained AST output publishes final metadata; actual changed hook/addon text retains preliminary metadata. The combined `esModule`/`Symbol.toStringTag` branch has a runtime regression after broad validation exposed a computed-property constructor argument error. CJS `exports: "none"` with a default-exporting entry is rejected by public option validation, so it is checked as a diagnostic rather than counted as successful factory execution.

`wrapped_formats` runs DCE/compress/mangle/full × IIFE/UMD for named/default/no exports and dotted `extend`, including external interop and duplicate/nested private fields. Node VM assertions execute IIFE browser globals and UMD browser/CJS/AMD branches, check live bindings, callback/acquisition counts and order, and validate serialized final-map anchors and unmapped generated closing glue.

Transferred import initialization now moves finalized statements through small owned AST fragments into the recipient arena, after all finalizers finish. Plain cloning clears semantic IDs and resets source spans, preserving ordered bindings without reparsing or attributing donor offsets to recipient source. `transferred_imports` covers two ordered CJS namespace transfers and donor uses across disabled/DCE/compress/mangle/full modes; final maps preserve real anchors and leave transferred declarations unmapped. The obsolete `PrependRenderedImport` mutation and the generic post-codegen mutation trait, storage and gate have been removed: no producer remained after the transfer moved to AST fragments. See [ast-mutation](../ast-mutation/implementation.md).

Whole-program wrapped printing filters donor comments by the module policy before applying the final-chunk policy to generated comments. Thus ordinary banner/footer comments survive non-whitespace-minified output, while module normal comments remain filtered; legal generated comments also survive that mode when `comments.legal` is false. Removed module comment anchors are placed inside the generated wrapper rather than at program offset zero, which would put them before an IIFE hashbang. `wrapped_formats::wrapper_comments_preserve_hashbang_and_addon_policy` checks both policies, valid hashbang placement, runtime results and serialized maps.

The dormant renderer `module_groups` representation and its text wrappers/hoisted-declaration path have been removed. Linking and chunk construction had no producer for this representation, including incremental rebuilds. Manual code-splitting groups are a separate active type and remain. Namespace sharing still excludes wrapped owners; removing the empty renderer group map must not accidentally admit them.

Arbitrary executable addons, callback addons and addon hooks use the actual rendered text as input to the shared optimizer after render hooks. String fragments can alter tokenization and statement boundaries across modules: `intro: "if (false)"` controls the first emitted statement, while an intro/outro block comment can suppress module text. Inserting empty-statement skeleton slots changes those semantics or loses the slots entirely. The adapter preserves the actual format renderer, preliminary module metadata, callback counts and source-map composition. `wrapped_formats` covers lexical closures with string/callback/hook providers, conditional first statements, cross-fragment comments and public parse diagnostics for invalid addon text. Builtin IIFE/UMD wrappers without arbitrary addons retain the complete AST route.

Additional implementation boundaries:

1. Broaden inline carrier validation, including transformed producer maps and per-carrier finalized names. Factory registrations, bridge declarations and live export getters are built programmatically around retained donor bodies; complete programs use whole-program printing rather than flat module splitting. `inline_carriers` checks independent load orders, once-only nested factories, live reads, bare calls, private fields, CJS members and per-copy source anchors.
2. Complete validation of programmatic Flat/IIFE/UMD construction, including default returns, raw directives and comment envelopes. Arbitrary addon text remains a parser input contract.
3. Broaden dev lifecycle validation. Dev graph registration now uses the same topology collector for text and programmatic AST output. Graph rows follow the runtime donor, or precede own modules when the runtime is imported; inline record rows run inside their factories after bridges. `dev_graph` checks full scan, changed partial scan and cached partial scan with inline carriers on/off and DCE/full minify, including sparse partial-accept bindings, dynamic reverse edges before/after lazy loading, entry rows, once-only execution, refreshed values and serialized source maps. Existing dev/HMR fixtures reach runtime checks before their snapshot differences. Property-mangling state/cache already has focused single/multiple-chunk coverage.
4. Arbitrary string-returning `renderChunk` hooks use the shared optimizer through the final-text parser adapter. Hook return/map semantics have focused coverage; removing the old pipeline does not imply zero reparsing under this plugin contract.

The final default-path Rust integration run completed 2,303 tests: 2,235 passed, none failed and 68 were ignored. The initially visible 24 failures hid five later assertions: three downstream content hashes and two later minify-target outputs. After the final ownership change and native rebuild, the Node main suite passed 1,431 tests with 20 skipped, and the watcher suite passed all 44 tests. Rollup compatibility passed 1,259 cases with zero failures and 119 ignores. The three newly ignored donor-source inventory cases are covered by `literal_provenance::eliminated_donor_sources_drive_ignore_list`, including retained-donor control and actual final-source ignore indices.

The earlier packed native API/CLI matrix passed all 64 cases, covering ESM/CJS/IIFE/UMD, changed/unchanged hooks, addons, inline carriers and DCE/compress/mangle/full, with runtime and serialized final-map assertions.
