# Chunk AST Minification — Implementation

## Summary

The opt-in `ROLLDOWN_CHUNK_AST_DCE=global` path assembles finalized module ASTs into one chunk program, compresses/mangles it, then prints module segments against a shared virtual source space. It avoids printing and reparsing the joined chunk. The implementation is still a PoC; full adoption validation remains open.

## Source maps

`crates/rolldown/src/stages/generate_stage/chunk_ast_dce/global.rs` rebases module spans into the shared source text. After printing, `remap` assigns each token to its original producer. A virtual owner can contain code moved from a real module, so its map must still be generated.

- A map containing only its real owner's source can defer transform-chain composition to the normal module renderer.
- Foreign producers are composed with their own transform chains. Their maps are final even when those chains are empty; the printed owner's chain must not be applied afterward.
- Virtual and generated source locations, and already-unmapped input tokens, produce explicit unmapped segments. Dropping these tokens would let a preceding mapping extend across generated code on the same output line, especially with whitespace minification.
- `compose_per_module` composes mapped tokens by producer and carries unmapped tokens through unchanged, then merges them in generated order. The unmapped segments must survive even when another producer has a transform chain. Composition may omit a producer's wholly unmapped line or repeated unmapped segments (for example after a plugin returns an empty map); preserve explicit unmapped segments at omitted generated positions before merging it with foreign producers on that same line. A foreign mapped producer can intervene between two such positions, so retaining only the line's first boundary is insufficient. `empty_producer_map_terminates_foreign_mapping` checks this boundary and both neighboring donors in serialized final maps, in DCE-only and full-minify modes.
- `rolldown_sourcemap::SourceJoiner` repairs `oxc_sourcemap` 9 concat chunk headers to carry the last mapped original line/column across unmapped fragment endings. Unmapped segments leave those VLQ baselines unchanged; using their placeholder coordinates corrupts the following fragment's serialized map even while its in-memory tokens remain correct. The serialization roundtrip regression covers mapped/unmapped endings, consecutive unmapped fragments, repeated sources, and name baselines.

The vendored `oxc_minifier` exposes `Minifier::with_literal_spans` and `Compressor::with_literal_spans`, enabled only by the global path when sourcemaps are requested. Builder methods preserve compatibility with existing `CompressOptions` struct initializers, including the native binding's upstream conversion. Constant inlining otherwise rebuilds literal nodes with the consumer identifier span, losing atomic donor origins entirely. The opt-in records original literal spans before normalization and carries their provenance through symbol aliases and direct AST moves. Composite folds keep consumer attribution. Consumers or donors with anchored comments also keep consumer attribution, preserving annotation placement and avoiding duplicated donor comments. The assembled compression program receives a copy of module comment metadata for this guard; module codegen continues to print the originals. Tracking adds an enabled-only initial AST scan and provenance/comment buffers; the disabled path does not allocate those buffers or scan the AST. See `vendor/oxc_minifier.patch`. Integration assertions in `literal_provenance`, `plugin_sourcemap_chain` and `sourcemap_audit` cover serialized donor positions, producer transform chains and consumer comments. The pinned MapLibre 6.16.0 audit exercises the native Node API across original/global × compress/mangle/full: all 54 selected upstream artifact tests pass, and all 64 inspected shader values retain exact donor mappings in each global mode. Identical shader values may share a real donor. Original compressed output retains consumer attribution, while its standalone source inventory still lists the donor. The now-unused JSON source can be absent from global compressed maps; source-list identity is not required.

The integration regression `full_minify/virtual_owner.rs` checks exact real-source locations and the adjacent virtual-code boundary with and without a producer transform map, in DCE-only and full-minify modes. The `global/tests.rs` unit regression also covers generated text, incoming unmapped segments, and restoration of a mapping after each boundary.

The `sourcemap_audit` integration regression checks original-source anchors in fifteen existing fixtures using serialized/reparsed final maps, including shorthand key/value pairs, imported CommonJS calls, destructuring and reference endpoints. `plugin_sourcemap_chain::composed_source_positions` checks a separate plugin-transform fixture in ordinary and full-minify modes, asserts that all three producers really run through the transform, and checks foreign-source positions after composition. Run these in separate original/global processes. They do not require the two paths' segment counts or synthesized punctuation anchors to be identical: inlined outer nodes retain reference spans, so direct codegen can use the reference's end while reparse/composition resolves to its start.

A synthesized block's closing brace must terminate mapped child coverage. The vendored codegen emits an explicit unmapped segment for an empty block closing span, and clears mapping deduplication state so the same original position can resume afterward. This is scoped to block/curly closing braces; synthesized call delimiters retain their existing reference-attribution behavior. Without this boundary, a minified CommonJS wrapper's closing glue inherits the last user statement's location. The regression checks the last real closing brace, every intervening generated byte, and the next real call; the codegen unit regression exercises the same transition without bundling.

## Splitting

The debug build compares the minifier's statement-address sequence with the flattened head/module/tail segments. Printing may change ownership attribution but must preserve statement order. Class offsets passed to codegen must follow that same traversal order for private-member mangling.

## Render hooks

The fast path runs before `renderChunk`; unrecognized render hooks must therefore fall back to the original pipeline. `Pluginable::is<T>()` checks the actual erased plugin type. Only `AssetModulePlugin`, `CopyModulePlugin`, and (under the `testing` feature) `HiddenModuleMarkersPlugin` are allowed; names supplied by custom plugins do not affect eligibility. The marker implementation lives in `rolldown_plugin_utils` behind its `testing` feature so core and harness share one concrete identity without a dependency cycle. Builtin asset/copy hooks additionally require per-chunk placeholder exclusion: see [plugin-asset-module](../plugin-asset-module/implementation.md).

## Ownership and concurrency

`owned.rs` consumes eligible `EcmaAst`s into a private `ChunkAst` before mutation. It detaches each whole `Program`, replaces its original root with an empty program, and retains the original `ProgramCell` intact as an arena/source keepalive. Do not use `ProgramCell::into_owner()`: Oxc arena vectors retain an `&Arena` inside the allocator object, so moving that allocator out of the cell invalidates retained vectors even if the arena buffers survive.

The chunk scratch allocator is boxed **before** any allocations, keeping its address stable when the chunk moves through Rayon and maps. The owner retains the shared source text **before** rebasing installs references. Programs are declared before donor cells, scratch and source keepalives, so all roots retire before backing storage during normal drop and unwinding. Preparation consumes the owner; a panic cannot leave partly changed roots accessible through the original AST table.

Only pre-assembly rebasing transfers individual `ChunkProgram`s between workers, while their donor arenas are still disjoint. Once bodies mix arenas, compression and splitting run serially per chunk. `PreparedChunk` is a frozen facade: its only shared operation prints a module into owned code/maps. It exposes no AST, semantic cells, allocator or generic callback. Its localized unsafe `Sync` implementation relies on codegen reading ASTs without mutating cells or allocating into their arenas. All readers join before consumption/drop. Cross-arena programs never re-enter an ordinary `EcmaAst`.

This retains parallel chunk preparation, span rebasing and module printing without cloning AST nodes, locks or per-node reference counts. It adds one boxed allocator and root/keepalive vector storage per eligible chunk; the disabled/fallback path does not construct these owners. Unit tests exercise allocator-address stability after owner/thread moves, scratch-vector growth, mixed-donor printing during unwind, source release and joined parallel readers. These tests and code review are not a substitute for Miri/sanitizer coverage.

## Module metadata

`RenderedModule.code` describes the printed fragment assigned to that module. In the global path it is the fragment **after chunk compression/mangling**. Inlining and statement merging can move code between module segments or into generated head/tail code. An emptied segment has `code: null` and `renderedLength: 0`; the module remains in `modules` and `moduleIds`. `renderedLength` counts UTF-16 code units of that fragment, not original-source contribution. Generated import/export glue is not added to an individual module's metadata. Fragments need not be independently executable.

This post-compression attribution is an accepted compatibility change for adopting the global path. It can change size reports and the inputs plugins use in `augmentChunkHash`. Module IDs and `renderedExports` retain link-stage identity: export names are original names retained by linking/tree shaking, even when their code is inlined elsewhere. Later chunk transformations do not update these stored fragments. The fallback pipeline still records module fragments before its late chunk minifier; exact text/length parity between the pipelines is not promised.

Keeping exact old metadata would require separately printing and retaining pre-compression module code, reintroducing printing and memory costs. The chosen contract uses the fragments already printed for output, with no additional production rendering or retained code.

`metadata_audit` asserts full/DCE behavior, movement into a consumer with an emptied donor, retained module IDs/export names, removal of unused exports, UTF-16 lengths using a non-ASCII marker, exclusion of generated export glue, and consistency across postBanner, augmentChunkHash, generateBundle and returned OutputChunk. It also checks that custom renderChunk hooks use fallback, including plugins named like builtins. Run it in separate processes with global mode enabled/unset.

## Path coverage

With the `testing` feature, `ROLLDOWN_CHUNK_AST_COVERAGE=/absolute/path.jsonl` records the first failed build/chunk gate, actual global execution, completed optimization/splitting, per-module printing, and whether the late text minifier runs or skips an AST-processed chunk. Records include cwd/output directory, preliminary chunk/module name, and normalized compress/mangle/property-mangle flags. The append-only writer is serialized for parallel jobs within one process; use separate trace files for separate Node processes/workers, since their writes to a shared path can interleave. No tracing code or file access is compiled into builds without `testing`. The trace is opt-in and is not a benchmark.

`path_coverage::execution_and_final_maps` exercises compress-only, mangle-only and full minify across cross-module inlining, duplicate/nested private fields, dynamic splitting, comment-only banners, and CJS/IIFE/custom-renderChunk/intro/code-banner fallback. Each process runs 27 builds and Node executions with concrete value/event-order assertions, checks 33 final maps and 60 exact original-source anchors, and optionally exports raw code/maps through `ROLLDOWN_PATH_MATRIX_OUTPUT`. Output directories distinguish pipeline/scenario/mode. The external audit runner checks that eligible ESM cases actually complete global optimization/splitting/printing and skip late minify, and that fallback cases actually run the original minifier. Run original and global in separate processes because mode selection is cached. Compare chunk graph roles/references rather than hashed filenames, which legitimately change with emitted bytes.

## Remaining validation

The reviewed fixture snapshots use global output as their expected text. Original/global builds can legitimately differ in layout and mapping granularity, so accepting global snapshots does not imply the original path passes the same snapshots. Preserve separate actual-output baselines when doing dual-path validation, run each mode in its own process with snapshot updates disabled, and compare actual code/maps rather than treating a shared snapshot match as correctness evidence. The local adoption audit retains both baselines and verifies the snapshot-update allowlist; a maintained dual-path CI baseline remains to be added.

The metadata decision, ownership encapsulation and focused path matrix do not replace the remaining full-adoption platform/API test matrix. CJS and IIFE in the focused matrix deliberately validate fallback; the global eligibility contract remains ESM-only.
